## 1. Текущий статус

### Основные функциональные модули

#### 1.1. Агентная система (Agents)
- **ProductAgent** (`src/agents/product_agent.py`) — основной агент для обработки запросов о товарах
  - Использует LangChain `create_agent` API (современный подход)
  - Поддержка семантического поиска товаров
  - SQL-фильтрация по параметрам (цена, вес, скидка)
  - Работа с историей диалогов
  - Кэширование агентов для оптимизации
  - Middleware для обработки ошибок инструментов

- **BaseAgent** (`src/agents/base_agent.py`) — абстрактный базовый класс для всех агентов
- **AgentFactory** (`src/agents/factory.py`) — Singleton-фабрика для создания и переиспользования агентов

#### 1.2. Инструменты (Tools)
- **SQL Tools** (`src/agents/tools/sql_tools.py`)
  - `generate_sql_from_text` — генерация SQL из текста на русском
  - `execute_sql_query` — выполнение SQL SELECT запросов
  - `get_table_schema` — получение схемы таблиц

- **Product Tools** (`src/agents/tools/product_tools.py`)
  - `vector_search` — семантический поиск товаров (векторный поиск)
  - `get_random_products` — fallback для получения случайных товаров

- **Media Tools** (`src/agents/tools/media_tools.py`)
  - Отправка изображений товаров через WhatsApp
  - Работа с фотографиями из каталога

- **Client Tools** (`src/agents/tools/client_tools.py`)
  - `get_client_profile` — получение профиля клиента

- **Context Tools** (`src/agents/tools/context_tools.py`) — управление контекстом агента

#### 1.3. API и роутинг
- **AI Router** (`src/routers/ai_router.py`)
  - `/ai/processConversation` — обработка сообщений пользователей (фоновые задачи)
  - `/ai/initConversation` — инициализация новой беседы
  - `/ai/resetConversation` — сброс истории беседы
  - `/ai/getProfile` — получение профиля клиента

- **Health Router** (`src/routers/health.py`) — проверка здоровья приложения

#### 1.4. База данных
- **PostgreSQL** через Supabase
- **Схема:** `myaso`
- **Основные таблицы:**
  - `products` — каталог товаров
  - `price_history` — история цен
  - `conversation_history` — история диалогов
  - `orders` — заказы
  - `clients` — клиенты

#### 1.5. Память и история
- **SupabaseConversationMemory** (`src/utils/memory/conversation_memory.py`)
  - Реализация `BaseChatMessageHistory` для LangChain
  - Хранение истории диалогов в Supabase
  - Асинхронная инициализация

#### 1.6. Мониторинг и трейсинг
- **LangfuseHandler** (`src/utils/callbacks/langfuse_callback.py`)
  - Трейсинг вызовов LLM
  - Отслеживание вызовов инструментов
  - Сохранение истории диалога

- **ReasoningLogger** (`src/utils/callbacks/reasoning_logger.py`)
  - Логирование процесса рассуждения агента
  - Метрики: количество вызовов LLM, использование инструментов

#### 1.7. Интеграции
- **WhatsApp Service** (`src/services/whatsapp_service.py`)
  - Отправка сообщений
  - Отправка изображений

- **OpenRouter** — провайдер LLM (через ChatOpenAI)
- **Supabase** — база данных и векторный поиск
- **ChromaDB** — векторная база данных (для embeddings)

### Выполненные задачи и этапы

### Текущие задачи/баги

#### 🔴 Критические проблемы
1. **Проблема с обязательным вызовом инструментов**
   - В `ai_router.py` добавлена подпись к `user_input` для принудительного вызова инструментов
   - Агент иногда отвечает без вызова инструментов (логируется как предупреждение)
   - **Расположение:** `src/routers/ai_router.py:47-51`, `src/agents/product_agent.py:577-584`

2. **Обработка ошибок памяти**
   - Проверки на `async_initialized` в нескольких местах
   - Возможны race conditions при инициализации памяти
   - **Расположение:** `src/agents/product_agent.py:284-292`, `src/routers/ai_router.py:122-125`

#### 🟡 Средние проблемы
3. **Кэширование агентов**
   - Кэш агентов может не обновляться при изменении промпта
   - Логика очистки кэша при изменении промпта может быть неоптимальной
   - **Расположение:** `src/agents/product_agent.py:207-245`

4. **SQL безопасность**
   - Валидация SQL запросов через регулярные выражения
   - Возможны обходы защиты через сложные конструкции
   - **Расположение:** `src/agents/tools/sql_tools.py:170-179`, `src/utils/validators.py`

5. **Таймауты и ограничения**
   - Фиксированные таймауты (60 секунд для агента)
   - Нет адаптивных таймаутов в зависимости от сложности запроса
   - **Расположение:** `src/config/constants.py:14-15`

#### 🟢 Мелкие проблемы
6. **Логирование**
   - Много комментариев "Не логируем ... - это не важно"
   - Непоследовательное логирование в разных модулях
   - **Расположение:** Разбросано по коду

7. **Документация**
   - Удален файл `docs/langchain_migration.md` (в git status)
   - Некоторые функции не имеют полной документации

## 2. Техническая архитектура

### Стек технологий

#### Backend Framework
- **FastAPI** (0.116.1) — асинхронный веб-фреймворк
  - Использование `BackgroundTasks` для неблокирующей обработки
  - Асинхронные endpoint'ы

#### AI/ML Framework
- **LangChain** (1.0.3) — фреймворк для работы с LLM
  - `create_agent` API для создания агентов
  - Middleware для контроля выполнения
  - Интеграция с инструментами через `@tool` декоратор

- **LangChain Community** (0.4.1) — дополнительные интеграции
- **LangChain OpenAI** (1.0.1) — интеграция с OpenAI-совместимыми API

#### База данных
- **PostgreSQL** (через Supabase)
  - `asyncpg` (0.30.0) — асинхронный драйвер PostgreSQL
  - Connection pooling для оптимизации

- **Supabase** (2.18.1) — BaaS платформа
  - REST API для работы с данными
  - Векторный поиск через Supabase

- **ChromaDB** (1.3.0) — векторная база данных для embeddings

#### LLM Provider
- **OpenRouter** — агрегатор LLM моделей
  - Использование через `ChatOpenAI` с кастомным `base_url`
  - Поддержка различных моделей через единый API

#### Мониторинг и логирование
- **Langfuse** (2.60.9) — трейсинг и мониторинг LLM приложений
  - Трейсинг вызовов LLM
  - Отслеживание использования инструментов

- **Sentry SDK** (2.35.2) — мониторинг ошибок
- **Python JSON Logger** (3.2.1) — структурированное логирование

#### Другие библиотеки
- **Pydantic** (2.11.7) — валидация данных и настройки
- **Uvicorn** (0.35.0) — ASGI сервер
- **Tenacity** (9.1.2) — retry логика
- **Backoff** (2.2.1) — exponential backoff

### Поток выполнения запроса

1. **Получение запроса** → FastAPI endpoint (`/ai/processConversation`)
2. **Валидация телефона** → нормализация и проверка формата
3. **Запуск фоновой задачи** → `BackgroundTasks.add_task()`
4. **Создание памяти** → `SupabaseConversationMemory(client_phone)`
5. **Получение агента** → `AgentFactory.create_product_agent()`
6. **Загрузка контекста** → промпты из БД, системные переменные, история
7. **Подготовка инструментов** → SQL, Media, Context tools (динамические)
8. **Выполнение агента** → `agent.run()` → `create_agent.ainvoke()`
9. **Вызов инструментов** → агент использует tools для поиска/фильтрации
10. **Сохранение результата** → память + Langfuse
11. **Отправка ответа** → WhatsApp Service

## 3. Основные проблемы

### Замедления/узкие места

#### 3.1. Производительность агента
- **Проблема:** Агент может выполнять до 15 итераций, каждая итерация = вызов LLM
- **Влияние:** Высокая задержка ответа (до 60 секунд таймаут)
- **Расположение:** `src/config/constants.py:14`, `src/agents/product_agent.py:371-377`
- **Решение:** Оптимизация промптов, кэширование частых запросов

#### 3.2. Векторный поиск
- **Проблема:** При `require_photo=True` выполняется поиск 250 документов, затем фильтрация
- **Влияние:** Избыточные запросы к векторной БД
- **Расположение:** `src/agents/tools/product_tools.py:53`
- **Решение:** Использовать фильтры на уровне векторной БД

#### 3.3. SQL генерация
- **Проблема:** Каждый SQL запрос = отдельный вызов LLM с полной схемой БД
- **Влияние:** Дополнительная задержка перед выполнением SQL
- **Расположение:** `src/agents/tools/sql_tools.py:108-185`
- **Решение:** Кэширование схемы, оптимизация промптов

#### 3.4. Загрузка промптов из БД
- **Проблема:** Множественные запросы к БД для загрузки промптов в каждом запросе
- **Влияние:** Задержка инициализации агента
- **Расположение:** `src/agents/product_agent.py:486-503`
- **Решение:** Кэширование промптов в памяти

#### 3.5. Connection Pooling
- **Проблема:** Использование connection pool, но нет мониторинга использования
- **Влияние:** Возможны проблемы при высокой нагрузке
- **Расположение:** `src/database/database.py`
- **Решение:** Мониторинг pool size, настройка параметров

### Технический долг

#### 3.6. Устаревшие паттерны
- **Проблема:** Комментарии о "не логируем" вместо правильной настройки логирования
- **Расположение:** Разбросано по коду
- **Решение:** Настроить уровни логирования через конфигурацию

#### 3.7. Дублирование кода
- **Проблема:** Повторяющаяся логика обработки ошибок в разных местах
- **Расположение:** `src/routers/ai_router.py`, `src/agents/product_agent.py`
- **Решение:** Вынести в общие утилиты

#### 3.8. Типизация
- **Проблема:** Использование `Any` в некоторых местах вместо конкретных типов
- **Расположение:** `src/agents/product_agent.py`, `src/agents/factory.py`
- **Решение:** Улучшить типизацию для лучшей поддержки IDE и статического анализа

#### 3.9. Тестирование
- **Проблема:** Отсутствие unit-тестов и integration-тестов
- **Решение:** Добавить тесты для критических компонентов

#### 3.10. Конфигурация
- **Проблема:** Жестко закодированные значения в некоторых местах
- **Расположение:** `src/agents/tools/product_tools.py:49` (лимит 50)
- **Решение:** Вынести в константы/конфигурацию

### Проблемы с поддержкой/масштабируемостью

#### 3.11. Масштабирование агентов
- **Проблема:** Кэширование агентов в памяти процесса (не распределенное)
- **Влияние:** При горизонтальном масштабировании кэш не разделяется
- **Расположение:** `src/agents/product_agent.py:152`, `src/agents/factory.py:78`
- **Решение:** Использовать Redis для распределенного кэша

#### 3.12. Обработка ошибок
- **Проблема:** Общие сообщения об ошибках для пользователя
- **Влияние:** Сложно диагностировать проблемы в production
- **Расположение:** `src/agents/product_agent.py:602-609`
- **Решение:** Улучшить логирование, добавить error tracking

#### 3.13. Мониторинг
- **Проблема:** Нет метрик производительности (latency, throughput)
- **Решение:** Добавить Prometheus метрики или использовать Langfuse более активно

#### 3.14. Безопасность SQL
- **Проблема:** Валидация через регулярные выражения может быть обойдена
- **Расположение:** `src/utils/validators.py`, `src/agents/tools/sql_tools.py:259-261`
- **Решение:** Использовать параметризованные запросы, whitelist разрешенных операций

#### 3.15. Управление версиями зависимостей
- **Проблема:** Некоторые зависимости зафиксированы на конкретных версиях
- **Расположение:** `requirements.txt`
- **Решение:** Регулярно обновлять зависимости, использовать `pip-audit` для проверки уязвимостей

## 4. Планируемый рефакторинг

### Цели рефакторинга

1. **Улучшение производительности**
   - Сокращение времени ответа агента
   - Оптимизация запросов к БД
   - Кэширование промптов и схем

2. **Улучшение читаемости кода**
   - Устранение дублирования
   - Улучшение типизации
   - Стандартизация логирования

3. **Улучшение масштабируемости**
   - Распределенное кэширование
   - Оптимизация использования ресурсов
   - Горизонтальное масштабирование

4. **Улучшение надежности**
   - Улучшение обработки ошибок
   - Добавление тестов
   - Улучшение мониторинга

### Зоны для рефакторинга

#### 4.1. Кэширование (Приоритет: Высокий)
**Текущее состояние:**
- Кэш агентов в памяти процесса

## 5. Дополнительные заметки

### Важные зависимости

#### Критичные зависимости
1. **LangChain 1.0.3** — основной фреймворк
   - Важно: API `create_agent` может изменяться в минорных версиях
   - Рекомендация: зафиксировать версию, тестировать обновления

2. **OpenRouter API** — провайдер LLM
   - Зависимость от внешнего сервиса
   - Рекомендация: добавить fallback на другой провайдер

3. **Supabase** — база данных и векторный поиск
   - Критичная зависимость для работы приложения
   - Рекомендация: иметь план миграции на другой векторный поиск

4. **WhatsApp API** — интеграция с мессенджером
   - Внешний сервис (`http://51.250.42.45:2026`)
   - Рекомендация: добавить retry логику, мониторинг доступности

#### Версии Python
- **Python 3.11** (из Dockerfile)
- Рекомендация: обновить до Python 3.12 для лучшей производительности

### Возможные риски

#### Технические риски

1. **Изменения в LangChain API**
   - **Риск:** Высокий — LangChain активно развивается
   - **Митигация:** Зафиксировать версию, мониторить changelog

2. **Зависимость от внешних API**
   - **Риск:** Средний — OpenRouter, Supabase, WhatsApp API
   - **Митигация:** Retry логика, fallback провайдеры, мониторинг

3. **Производительность LLM**
   - **Риск:** Средний — задержки ответа LLM
   - **Митигация:** Кэширование, оптимизация промптов, таймауты

4. **Масштабирование**
   - **Риск:** Средний — рост нагрузки
   - **Митигация:** Горизонтальное масштабирование, кэширование, оптимизация

5. **Безопасность SQL**
   - **Риск:** Высокий — SQL injection через LLM
   - **Митигация:** Улучшенная валидация, whitelist операций, тестирование

#### Бизнес-риски

1. **Стоимость LLM вызовов**
   - **Риск:** Высокий — каждый запрос = несколько вызовов LLM
   - **Митигация:** Кэширование, оптимизация промптов, мониторинг использования

2. **Качество ответов агента**
   - **Риск:** Средний — агент может давать неточные ответы
   - **Митигация:** Улучшение промптов, мониторинг через Langfuse, A/B тестирование

3. **Зависимость от одной модели**
   - **Риск:** Низкий — можно переключиться на другую модель через OpenRouter
   - **Митигация:** Абстракция провайдера LLM
